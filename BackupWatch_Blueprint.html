2. System Architecture & Data Flow

[ SPFx Web Part — SharePoint Online ]
   ├─ Loads on page render, authenticates silently via AadHttpClient SSO.
   ├─ Dispatches authenticated GET to Azure Function (with Bearer JWT) to load dashboard data.
   └─ Dispatches authenticated POST to `/api/escalate` to create tickets for selected issues.
         │
         ▼
[ Azure Function — backupwatch-api ]
   ├─ Easy Auth validates JWT (tenant ID + audience check).
   ├─ Cache HIT? → Serve dashboard data from memory cache instantly.
   ├─ Cache MISS? (for GET) → Executes concurrent async fetches:
   │     ├─── GET /v1/bcdr/device → List of all BCDR appliances.
   │     ├─── GET /v1/bcdr/device/{serial}/asset → Agents + volumes per appliance.
   │     ├─── Table Storage (Exclusions) → Load active exclusion rules.
   │     └─── Table Storage (TrackedTickets) → Fetch list of tracked tickets.
   │            └─ Bulk query AutoTask `/Tickets/query` for status of tracked tickets.
   │            └─ Prune completed tickets (Status ID 5) from Table Storage.
   │            └─ Enrich payload with active ticket status/URLs (ticketReference).
   └─ For POST `/api/escalate`:
         ├─ Lookup device serial number in AutoTask `/ConfigurationItems` to match Company ID & Asset ID.
         ├─ Fallback: Lookup company by name in AutoTask `/Companies` if no native asset mapping.
         ├─ Post ticket creation payload to AutoTask `/Tickets` with custom API headers (UserName & Secret).
         └─ Write stateful entry to `TrackedTickets` table to prevent duplicate escalations.
         │
         ▼
[ AutoTask REST API & Storage Systems ]
   ├─ AutoTask: Processes REST requests (requires custom `UserName`, `Secret`, and `ApiIntegrationCode` headers).
   └─ TrackedTickets Table: Tracks active ticket IDs indexed by Serial Number and Issue Key.

3. Active Features (v1.5.1)

🗂️ Subscription Tabs & Storage

Separates appliances into active and cancelled tabs, and provides storage bar gauges directly on the appliance rows.

  • Active Subscriptions tab — displays active appliances and their agents.
  • Cancelled Subscriptions tab — hides cancelled appliances to avoid clutter.
  • Storage Metric Bars — displays Used vs. Total storage color-coded by usage severity.

⏳ Last Seen heartbeats

Displays exactly when each Datto appliance last checked in with Datto Cloud monitoring:

  • Relative time string (e.g. "15m ago") is rendered in a dedicated column.
  • Color-coded indicators: Green (checked in < 30m), Amber (30m - 2h), and Red (checked in > 2h ago).

🎫 AutoTask Ticket Escalation

Enables operators to escalate alerts directly to AutoTask from the dashboard with zero manual mapping:

  • Native Asset Linking: Queries AutoTask for the device configuration item by serial number.
  • Deduplication: Prevents duplicate tickets. If an issue is already open, the Escalate button is replaced with a direct link (e.g. "🎫 Ticket #12345 (New)").
  • Automatic Triage Note Updates: If the error message changes while a ticket is still active, the dashboard automatically adds a Detail Note to the ticket.

🚫 Exclusions Management

Granular exclusion rules allow operators to mute specific alert types, devices, or volumes:

  • Exclusions count badges are shown on the appliance level.
  • Individual excluded volumes are listed with their exclusion notes inside the agent sub-grid.
  • Archived agents are excluded from counts automatically to prevent false positives.
